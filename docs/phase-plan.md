# Phase plan

This plan is the durable record of what trafilatura-rust ships next and the items still open. It
holds current state only; history is in git. `AGENTS.md` holds the porting rules every phase works
under and `docs/architecture.md` the runtime contract; this plan does not restate them.

How the plan is kept:

- A phase runs its own brainstorm and design gate before code; nothing here pre-decides its design.
  Design specs and implementation plans are working files under `.superpowers/` (not tracked); once a
  design is approved, the decisions that outlive the phase move into `AGENTS.md` and the pages under `docs/`.
- A row moves from Remaining to Shipped when its done-when criteria hold, citing the commit or tag.
- A register row leaves the register when it closes. Ids are never reused: `OI-n` for open items,
  `F-n` for followups.
- A citation of this plan names an id or a heading, never a line.

## Roadmap

The parity bar for every phase is upstream Python output at the pinned release with `fast=True`
(D-1), compared by the parity harness Phase 2 builds.

Phase 8 shipped as these sub-phases, in this order; each was one review unit.

| Sub-phase | Status | Scope |
| --- | --- | --- |
| 8a. Input cap and binary shortcut | Shipped in `fa4181d` | A cap on raw input (`max_input_bytes`, default 64 MiB, `Rejection::InputTooLarge`, a deviation: upstream's `extract` caps only decompressed input), checked in `load_html` before decompression or any copy. An early `None` for binary input (zip, PDF, images, and gzip or zstd that failed to decompress) by magic bytes after decompression, each magic checked with the oracle |
| 8b. Attribute bounds | Shipped in `35a99ef` | A lexical scan before each chunk reaches html5ever rejects a tag of more than 1,000 attributes, since html5ever's duplicate-attribute check is quadratic in the attributes of one tag; html5ever stays unpatched. The sink's `add_attrs_if_missing`, called for each repeated `<html>` or `<body>` tag, is quadratic across tags and gets a constant-time lookup and the same cap. Two budgets bound html5ever's tree builder, both scaled from `max_nodes`: the attributes created per parse, clones included, at 10 per allowed node, and the compare work of its formatting-element handling at 40 units per allowed node, where the parse stops at the first token after a budget is crossed. All extend D-5 |
| 8c. Parse and extraction peak | Shipped in `0400519` | Text moved, not copied, from the sink into `Tree` in `Inner::convert`, with the arena reserved first. `script` and `style` text dropped by `parse_document` for extraction, except JSON-LD and `settings+json` scripts, the only ones read with metadata off; the parity tree dump and fragment parses keep it. An extraction whose dropped text would be read re-runs on a full parse. The backup copy of `prepare_tree` skipped where nothing reads it (the backup of the forum path and of slow mode stays) |
| 8d. Superlinear output paths | Shipped in `36ed344` | Ordered list items are numbered from a running count of the preceding items, carried by the walk in `xml`. `merge_adjacent_hi` merges each run of adjacent mergeable `hi` in one pass. `escape_and_convert_math` escapes text without `\[` or `\(` without the per-character math scan |
| 8f. Hot paths | Shipped in `0e90e4d` | `pystr::is_space` and `pystr::is_printable` answer ASCII with a range match and consult the Python tables only for other characters. `trim` builds its result in one string; the link-density counts and the form counts of `handle_forms` walk the text pieces instead of building the text. `tree_cleaning` walks the tree once to find which cleaning tags occur and runs the live walk only for those. `repair_faulty_html` runs the `INVALID_XML_CHARS` regex only when a pre-scan finds a matching character, and rebuilds the doctype line only when it changes or has no newline. `sanitize` writes one string, and `line_processing` replaces the entities only in a line with `&`. The `unescape` prefix fallback tries at most the longest legacy entity name (`LEGACY_NAME_MAX_CHARS`). `determine_returnstring` strips its output in place and replaces it only when normalization changes it |
| 8e. Fuzz | Shipped in `accc975` | Two `cargo-fuzz` targets in the standalone `fuzz/` crate: `parse_document` on arbitrary `str` and `Extractor::extract` on arbitrary bytes with the `decompress` feature, both asserting no panic, bounded time and bounded memory. `scripts/fuzz.sh` runs them with `-max_len` 1 MiB, `-timeout` 37 s (5 times the slowest 1 MiB linear page, 7.3 s for `extract` under AddressSanitizer) and `-rss_limit_mb` 6144 (2 times the peak of a linear page at the input cap, 2.9 GiB for `extract`, rounded up to a multiple of 1024); a linear page at the input cap passes at 64 times the timeout. They run on the stable toolchain with AddressSanitizer through the `x86_64-unknown-linux-gnuasan` target, locally in a Docker image (`scripts/fuzz.ps1`, `scripts/fuzz.Dockerfile`) and weekly in `quality.yml`, 15 minutes per target |
