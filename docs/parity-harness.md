# Parity harness

How crate output is compared with upstream Python: the fixture generator, the archive, the classes of
mismatch, the test and the measurement. Read it before touching `tools/parity/`, `tests/parity.rs`,
`tests/common/`, `scripts/fixtures.*`, `scripts/measure.*`, `scripts/oracle.*` or the fixture archive.

Two tests compare the crate with the fixtures: the parsed tree and the `txt`, `markdown` and `html` output.
The fixtures also hold the `xml`, `xmltei` and `json` outputs and the metadata fields; the metadata and
output-format phases of `phase-plan.md` start comparing them.

## Corpus and fixtures

Fixtures are generated by `tools/parity` and stored as one tracked archive.

- Corpus: pages are read from an upstream checkout at the pin (`$TRAFILATURA_UPSTREAM`, else
  `../trafilatura`): every HTML page in `tests/eval/` and `tests/cache/`, every `*.html` file in
  `tests/resources/`, and `tests/resources/webpage.html.gz`. No page is copied into this repo: they
  are third-party content upstream's license does not cover. The generator has no switch for extra pages.
- Generator: `tools/parity/` (the only Python in the repo, locked by `uv.lock`) runs upstream at the
  pin on Linux, where lxml bundles libxml2 2.14.6, and writes `.temp/fixtures/<version>/`, where
  `<version>` is the upstream `version` in `Cargo.toml`. The generator refuses a checkout at another
  commit.
- Two variants per page: `lxml` is upstream as is and is only reported; `html5` is upstream with
  `utils.fromstring` and `baseline.fragment_fromstring` replaced by an HTML5 parse (html5lib) copied
  into `lxml.html` elements, and crate output must match it exactly.
- Each variant holds the tree dump, the output of every format (`txt`, `markdown`, `html`, `xml`,
  `xmltei`, `json`), the metadata fields, and `errors`, the upstream exception per step if any.
  Generation is deterministic: `fast=True`, `dedup=False`, a full `date_params` dict with the fixed
  `max_date` (`MAX_DATE` in `tools/parity/parity/__init__.py`), one fresh extractor per page. The
  crate runs the comparison with the same `max_date`.
- `index.json` records `pin` (commit), `upstream_version`, `max_date` and `lock_sha256` of `uv.lock`,
  and lists the pages (`id`, `source`, `valid_utf8`). `f1.json` holds upstream's own F1 scores over
  `tests/evaldata.json` (fast runner), a quality signal, not a gate. Comparing crate F1 with it is
  planned.
- A full run builds the whole set in `<version>.new` and swaps it in by renaming, so a failed run
  leaves the previous set; it removes the `.new` and `.old` of a crashed run first and fails when one
  is locked. A filtered run (`--only`) renames each file into place and `index.json` last, so a crash
  never leaves a torn file.
- Copy rule for the `html5` tree: attributes whose name is not a valid XML name are dropped and
  XML-invalid characters are stripped, because lxml cannot store them. The comparator applies the same
  rule to crate output (`DumpMode::Normalized`); the crate keeps everything.
- Tree dump: one line per node in document order, indented by depth; local name (namespace only for
  SVG and MathML), attributes sorted by name, text and tail as JSON strings with whitespace kept; no
  comments, doctype or processing instructions.

## Archive

Generating takes about 10 minutes, so the set is packed (zstd level 19, about 23 MiB) into
`tools/parity/fixtures/fixtures-<version>.tar.zst`, one archive per upstream release, and committed.

- The commit stays the integrity anchor: `parity.pack` refuses a set whose `index.json` has another
  `pin` (commit) or `upstream_version`, or that is a filtered set (no `f1.json`).
- `parity.pack` writes `<archive>.tmp` and renames it into place, so an archive that exists is whole.
- The archive is the single tracked exception to "no third-party content in the repo": it holds
  extracted text and tree dumps, not pages, and it spares CI and agent test runs the generation.
- `scripts/fixtures.sh` unpacks it into the git-ignored `.temp/fixtures/<version>/` and does nothing
  when that directory exists; delete the directory to unpack again. Unpacking needs only a tar that
  reads zstd (`zstd` on `PATH`, or bsdtar), no Python or Docker. `--generate` runs `tools/parity` with
  `uv` on Linux and in Docker elsewhere, both from `tools/parity/uv.lock`.
- After a change to the generator, delete the archive and `.temp/fixtures/<version>`, run
  `scripts/fixtures.sh --generate --pack`, and commit the new archive. A `uv.lock` change needs the
  same only when it can alter upstream's output: a bump of `lxml`, `htmldate`, `courlan`, `justext`,
  `charset_normalizer`, `html5lib`, or of a package they depend on (`dateparser`, `babel`, `tld`). A
  security bump of anything else does not. A bump that can alter upstream's output, and a change of
  the oracle image's Python, also mean rerunning every generator of the generated test data below
  (each one runs upstream, lxml, html5lib or the image's Python) and committing the files that
  change. The archive's `lock_sha256` is the lock it was generated
  with, so it may differ from the current lock. The one place the two are compared is a filtered run
  (`scripts/fixtures.sh --only`): on a mismatch it starts a new index from that run's pages and deletes
  `f1.json`, so run it only after a full `--generate`. A new release gets a new archive name
  (`upstream-sync.md`).

## Tree classes

The tree dump is compared line by line: expected and actual are aligned with a Myers diff (`similar`,
`tests/hunks/mod.rs`) and each hunk (a run of removed and inserted lines) gets the first class that
applies. A page's classes are the set of its hunk classes; the test fails when any hunk is `port-bug`.
Only `decompress` and `upstream-error` apply to the whole page, because there is no crate tree to
compare. A dump that is `None` on one side (an empty tree against a tree) is a whole-page `port-bug`.

| Class | Meaning |
| --- | --- |
| `match` | crate tree equals the `html5` fixture |
| `encoding` | input is not valid UTF-8 (D-3), the hunk has as many removed as inserted lines, and each pair is equal once every non-ASCII char is removed |
| `python-parser` | html5lib predates a WHATWG rule html5ever follows (`PYTHON_PARSER_TAGS` in `tests/hunks/mod.rs`): every hunk line lies inside an unchanged element of that list, both sides hold the same text, the fixture side holds no element line and the crate side adds no element of that list (html5lib only drops tags, so a dropped or added `option` or a changed attribute stays `port-bug`) |
| `html5lib-cell-space` | html5lib 1.1 has no `processSpaceCharacters` in its table cell phase, so whitespace-only text in a `td` or `th` skips "reconstruct the active formatting elements", which html5ever and WHATWG do: one expected text line `ws+rest` against a formatting element (`a`, `b`, `i`, ...) holding `ws`, then the text `rest`, inside an unchanged `td` or `th` |
| `port-bug` | a hunk no rule above explains |
| `decompress` | compressed input without the `decompress` feature (D-4), whole page |
| `upstream-error` | upstream raised while building the `html5` tree, whole page |

There is no `normalized` hunk class: the fixture and the crate dump go through the same copy rule, so
lines it changes are equal on both sides and make no hunk. The report also counts `parser`: pages whose
`lxml` and `html5` fixtures differ (D-2). It is a count, not a class. The report is
`.temp/parity/report.md`: pages and hunks per class, the pages of each class, and the diffs of the first
pages that differ, pages with a `port-bug` hunk first.

## Output check

`outputs_match_html5_fixture` in `tests/parity.rs` runs `Extractor::extract` over every page in `txt`,
`markdown` and `html` and compares the text with `fixture["html5"]["formats"][format]`. The input is
`Input::bytes` of the upstream file and the options are the ones the fixtures were generated with
(`fast=True`, `dedup=False`, no metadata, no URL). A page whose fixture holds no text and no error must be
rejected by the crate with any `Rejected` error. The expected `html` text goes through
`strip_lxml_namespaces` first, which removes the ` xmlns:nsN="..."` declarations and the `nsN:` tag
prefixes lxml writes for foreign elements of the html5 tree, because the crate writes such an element by
its local name (D-2); the test fails when any are left.

When both sides have text, the two are aligned line by line as in the tree check and each hunk is
classified; the first rule that applies decides the output, and the test fails on any `port-bug` hunk:

| Class | Meaning |
| --- | --- |
| `match` | equal text, or no text upstream and a `Rejected` error from the crate, whole output |
| `decompress` | compressed input without the `decompress` feature (D-4), whole output |
| `upstream-error` | upstream raised and the crate returned a `Rejected` error, whole output |
| `normalized` | the page is listed in `NORMALIZED_REJECTS`: the crate rejects it with `InvalidValue` where upstream extracted text, because the oracle's normalized tree dropped an element whose name is not an XML Name (D-2), whole output (empty list today) |
| `encoding` | per hunk: input is not valid UTF-8 (D-3), as many removed as inserted lines, and each pair equal once non-ASCII chars are removed, or once a run of whitespace and non-ASCII chars counts as one space (upstream decodes some bytes to characters Python's `str.split()` counts as whitespace, where the crate's cp1252 guess gives a printable one); whitespace not next to a non-ASCII char must match |
| `port-bug` | any other hunk, or text on one side only |

The report is `.temp/parity/output-report.md`: per format the outputs and hunks of each class, the
outputs of each class other than `match` (with the reason of a `normalized` page) and the diffs of the
first outputs that differ, outputs with a `port-bug` hunk first.

## Test and measurement

- The parity test needs the `__internals` feature, which `cargo test --all-features` enables. It
  checks for fixtures when it runs and returns early, naming `scripts/fixtures.sh`, when they or the
  upstream checkout are missing, so `cargo test` works without Python or Docker.
- With `PARITY_REQUIRE_FIXTURES` set, missing fixtures or an index without pages fail the test
  instead. CI's Ubuntu job unpacks the archive and sets it, and uploads the report as an artifact;
  the Windows job does not unpack fixtures, so its parity test skips.
- `scripts/measure.sh` (or `.ps1`) measures, into `.temp/measure/<version>.json`, time (5-run median)
  and heap per page of the corpus. The Rust side covers `load_html` (decode plus parse) and `extract`
  (TXT, which repeats both) with the keys `loaded`, `median_ns`, `extract_ok`, `extract_median_ns`,
  `extract_alloc_bytes`, `extract_alloc_count` and `extract_peak_bytes`, and also the synthetic pages
  below. The Python side covers decode plus parse only: the comparison with upstream is `load_html`
  alone, and an upstream extraction number is part of Phase 9. Heap is comparable only on the Rust side:
  tracemalloc misses the lxml tree. Run it by hand; the numbers depend on the machine. A full run of
  the Rust targets takes about five minutes, and the largest page (`data_table_20m`) peaks at about 1 GB of heap.
- Synthetic pages: `tests/measure/mod.rs` builds the pages no corpus page reaches (D-5, D-9, the
  ordered-list numbering of Phase 8) and each target runs them once, without warm-up, writing
  `.temp/measure/<version>-rust-<kind>-synthetic.json` beside the corpus file. `large_page` has 1.1M
  `<p>` elements and a 10x10 table, above the default parse limit (`max_nodes` raised to 2,000,000).
  `node_limit` has 499,000 `<p>` elements and `node_limit_over` 501,000, both with default options:
  the first is `ok`, the second `too_large` (`DEFAULT_MAX_NODES` is 500,000). `cell_budget` is a table
  of exactly `MAX_OUTPUT_NODES` cells (10,000 rows of colspan 100) and `cell_budget_over` has one row
  more; the target fails after writing when an outcome differs from the page's expected one (`ok`,
  or `too_large` for `Rejected(TreeTooLarge)`). `ordered_list_50k` and `ordered_list_200k` are
  Markdown lists of 50,000 and 200,000 items inside `<article>` (a bare `<ol>` in `<body>` is flattened
  and never reaches `xml::list_marker`); the heap target skips them, because dhat would multiply their
  runtime (the 200k list alone takes about 150 s). A synthetic entry holds `name`, `input_bytes`,
  `expected`, `outcome`, and `output_bytes` and `elapsed_ns` (time) or `alloc_bytes`, `alloc_count` and
  `peak_bytes` (heap).
  The large-page pages have the shapes of large real pages, and `Nm` in a name means N MiB of input:
  `inline_script_20m` and `inline_script_50m` (one `<script>` of JavaScript), `json_ld_20m` and
  `json_ld_50m` (one JSON-LD script), `csv_pre_20m`, `csv_pre_33m` and `csv_pre_50m` (one `<pre>` of
  text), `data_table_20m` (a table of 3-cell rows, `max_nodes` raised to 2,000,000, `too_large` at the
  output limit) and `recall_rerun_20m` (a 20 MiB script on a page whose recall extraction reverts to its
  pre-cleaning copy, a page that extracts twice once script text is dropped).
- `scripts/oracle.sh 'CODE'` (or `.ps1`) runs one Python snippet with upstream importable at the pin
  and prints its stdout: the way to get an expected value for a ported test. It runs where
  `scripts/fixtures.sh` runs (uv on Linux, Docker elsewhere), so lxml is libxml2 2.14.6 in both.

| Variable | Used by | Effect |
| --- | --- | --- |
| `TRAFILATURA_UPSTREAM` | Rust tests, scripts, `tools/parity/tests` (the generator takes `--upstream`) | upstream checkout; default `../trafilatura` |
| `TRAFILATURA_FIXTURES` | tests | fixture directory instead of `.temp/fixtures/<version>` |
| `PARITY_REQUIRE_FIXTURES` | parity test | missing fixtures fail instead of skip |
| `TRAFILATURA_MEASURE` | `measure_time`, `measure_heap` | `1` lets the targets run; they skip otherwise |
| `TRAFILATURA_MEASURE_ONLY` | measure targets | unset: the corpus, then the synthetic pages; `synthetic`: only the synthetic pages, the corpus file untouched; any other text: only the corpus pages whose source path contains it |
| `TRAFILATURA_MEASURE_RUNTIME` | `parity.measure` | labels the host of a Python measurement: `docker` inside the container, `native` by default, so a table says when the two sides ran on different runtimes |

## Generated test data

Rust test files that hold values from upstream Python are written by generators in
`tools/parity/parity/`, run through `scripts/oracle.sh`: upstream at the pinned commit (the script
refuses another one), the packages of `uv.lock` and the oracle image's Python. Each file carries an
`@generated` header with its regenerate command and is never edited by hand; a rerun on the same pin
writes it byte for byte.

| Generator | Writes | Holds |
| --- | --- | --- |
| `gen_printable.py` | `src/pystr/printable.rs` | the `str.isprintable` ranges of the image's Python |
| `gen_decimal.py` | `src/pystr/decimal.rs` | the run starts of the `Nd` decimal digits of the image's Python |
| `gen_printable.py` (`alpha`) | `src/pystr/alpha.rs` | the `str.isalpha` ranges of the image's Python |
| `gen_nfc.py` (`tables`) | `src/pyunicodedata/nfc.rs` | decompositions, combining classes, composition pairs and the quick-check sets behind `unicodedata.normalize("NFC", ...)` of the image's Python |
| `gen_nfc.py` (`cases`) | `src/pyunicodedata/cases.rs` | NFC of every character with a decomposition or combining class (alone and between `a` and U+0301), of every composition pair and of two Hangul jamo sequences |
| `gen_xpath_cases.py` | `src/xpaths/cases.rs` | the matches of every upstream selector on HTML snippets |
| `gen_url.py` (`tables`) | `src/pyurl/tables.rs` | the NFKC netloc breakers of the image's Python |
| `gen_url.py` (`cases`) | `src/pyurl/cases.rs` | `html.unescape`, `urlsplit`, `urlunsplit`, `urljoin` and the two `courlan` helpers on URL strings |
| `gen_html_processing_cases.py` | `src/html_processing/cases.rs` | the tree upstream leaves after `tree_cleaning`, `prune_html`, `convert_tags`, `prune_unwanted_nodes` and `delete_by_link_density` on HTML snippets, with the options each case sets |
| `gen_main_extractor_cases.py` | `tests/main_extractor_cases/cases.rs` | the seven element handlers on `etree.fromstring` snippets, and `extract_content` or `extract_comments` then `extract_content` on HTML snippets, each with the options it sets and built with `fast=True` (D-1); results are tree dumps and texts |
| `gen_xml_output_cases.py` | `tests/xml_output_cases/cases.rs` | the TXT, Markdown and HTML output of `etree.fromstring` snippets and of the bodies the html snippets of `gen_main_extractor_cases` extract (imported, not copied), built with `fast=True` (D-1); an output is the text or the exception upstream raises |
| `gen_extraction_cases.py` | `tests/extraction_cases/cases.rs` | `extract` in TXT, Markdown and HTML on the html snippets of `gen_main_extractor_cases` (imported) and on pages for each branch of the cascade, and `baseline` with `html2txt` on JSON-LD and Discourse pages, built with `fast=True` (D-1) and `dedup=False` inside the html5 parser swap; results are the text, `None` or the exception class |
| `gen_repeated_output_cases.py` | `tests/repeated_output_tests/cases.rs` | the sets of upstream's `repeated_output_tests.py` re-derived with `fast=True` (D-1) inside the html5 parser swap: the keys of `test_no_repeated_words` whose result is `None` or repeats a word (upstream's reason kept for a key it lists too), and the comment-list triples that repeat; the file is imported by path from the checkout, and the generation fails when one of the three plain upstream assertions does not hold in fast mode |

Regenerate one with `scripts/oracle.sh 'from parity.<generator> import main; main()' > <file>`;
`gen_url` and `gen_nfc` take `tables` or `cases` in place of `main`, `gen_printable` `alpha` for `alpha.rs`. The files that hold HTML snippets carry the
`treedump` of the html5lib tree next to each snippet, and their tests first check that the crate's
parse dumps the same: a snippet that parses differently is changed, never the expectation.
`cases_match_upstream` of `html_processing` then runs the operation and compares `dump_from` (normalized
mode) of the result with the dump upstream wrote. A case there may state that its operation must change
the tree, and the generator fails when it does not.

The cases of `main_extractor` run as an integration test, `tests/main_extractor_cases.rs`, not beside
the module: half of them start from `etree.fromstring` snippets of converted tags, and the builder
(`xml_tree`) lives in `tests/trees`. `xml_cases_match_upstream` runs a handler on such a snippet and
compares the dumps of its result and of the whole snippet afterwards; `html_cases_match_upstream` runs
`tree_cleaning`, `convert_tags` and the extractor on an HTML snippet and compares the dumps and texts of
the bodies. Every `Extractor` the generator builds uses `fast=True`, because the crate takes upstream's
fast path (D-1). `scripts/oracle.sh 'from parity.gen_main_extractor_cases import report; report()'`
lists the lines of upstream's `main_extractor.py` that no case reaches; a sync that adds a branch
shows up there.

The cases of `xml_output_cases` run as an integration test too, `tests/xml_output_cases.rs`.
`xml_cases_match_upstream` builds each snippet with `xml_tree` and `html_cases_match_upstream` builds
the bodies with `run_pipeline`, the html pipeline `tests/trees` shares with `tests/main_extractor_cases.rs`
(`tree_cleaning`, `convert_tags`, then `extract_content` or `extract_comments` and `extract_content`).
Each tree gives three outputs: `xml_to_text` without and with formatting, and `build_html_output` on a
copy (`Tree::tostring` with `pretty_print`, stripped). The crate has one error, `Rejection::InvalidValue`,
for the `ValueError` and the `KeyError` upstream raises, so either name in a case matches it. The
generator rejects an xml snippet that `xml_tree` would read differently from `etree.fromstring`: one
with `&#`, a carriage return, a tab or newline in an attribute value, or an `svg` or `math` element.
The escapes those would test are unit tests of `Tree::tostring` in `src/dom/tests.rs`. In an html
case a foreign element reaches the output because the html5 tree keeps it; `Tree::tostring` writes it by
its local name, as a libxml2 tree does, while lxml on the oracle's html5 tree writes `ns0:` prefixes, so the
generator strips them from the expected HTML (D-2) and prints how many cases it touched.

The cases of `extraction_cases` run as an integration test too, `tests/extraction_cases.rs`.
`extract_cases_match_upstream` runs each case through the public `Extractor::extract` with the format and
options of the case: `None` matches any `Rejected` error and a raised exception matches
`Rejection::InvalidValue`. `baseline_cases_match_upstream` runs the internal `baseline` and `html2txt` with
cleaning. Every page is a full `<html>` document except the empty load: a fragment such as `"123"` fails the
crate's emulation of lxml's length check, which the html5 swap does not make, so it is a unit test with the
plain-lxml value. A snippet page runs in the three formats under its own options, then in `txt` with
`precision`, `recall` and comments off, then in `markdown` with formatting on (its default); that last run
stays only when it expects something other than the same page without formatting, and a baseline page runs
in `markdown` on the same terms against `txt`. A targeted page is checked while generating against a trace of
`trafilatura_sequence` (wrappers around `_forum_thread_page`, `baseline`, `html2txt` and `_recall_retry`, and
the salvage log line), so a page that misses its branch fails the generation. A page may also state a text its
`txt` output must or must not hold: the forum markers, which only a forum turns into output, and the stage
thresholds (250, 3000, the page share, the ratio, the retry floor), where the page on one side gains text from
the stage (a discard-class paragraph the baseline recovers, a teaser block the recall retry keeps) and the page
on the other side does not, so a `<` for a `<=` in the cascade changes an output. The generator prints the
counts per kind to stderr. Pages that nest thousands of levels are unit tests, not cases.
